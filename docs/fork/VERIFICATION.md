# Verification

How the fork is built and tested. Commands run from the repository root in WSL Ubuntu
(`wsl -d Ubuntu --exec bash -lc 'cd <repo> && …'`). Device test output goes to `build/device-results/` (not committed).

## 1. Build, lint, JVM tests

(`.github/workflows/ci.yml` runs the same, started by hand once just before a release; pushes and pull requests do not
start it, so this local run is the check while changes are made.)

```
bash scripts/wsl-gradle.sh assembleDebug lintDebug testDebugUnitTest
```

`scripts/wsl-gradle.sh` selects the JetBrains JDK 21 required by `gradle/gradle-daemon-jvm.properties`. Protocol and
DLNA tests are skipped here (no fixture servers) and run in step 2.

**In a Claude Code cloud session** (Linux container, no Android SDK, no KVM) the same check runs after a one-time setup:

```
# Android SDK (cmdline-tools from dl.google.com) and the pinned JetBrains JDK (sha256 as in ci.yml)
mkdir -p ~/android-sdk/cmdline-tools && cd ~/android-sdk/cmdline-tools \
  && curl -fsSL -o ct.zip https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip \
  && unzip -q ct.zip && mv cmdline-tools latest && rm ct.zip
yes | ~/android-sdk/cmdline-tools/latest/bin/sdkmanager --licenses >/dev/null
~/android-sdk/cmdline-tools/latest/bin/sdkmanager --install "platforms;android-34" "build-tools;35.0.0"
mkdir -p ~/dev/jdks/jbrsdk-21.0.11-linux-x64-b1163.116 && curl -fsSL -o /tmp/jbr.tar.gz \
  https://cache-redirector.jetbrains.com/intellij-jbr/jbrsdk-21.0.11-linux-x64-b1163.116.tar.gz \
  && tar -xzf /tmp/jbr.tar.gz -C ~/dev/jdks/jbrsdk-21.0.11-linux-x64-b1163.116 --strip-components=1
chmod +x gradlew && git config core.fileMode false   # the checkout may lose the executable bit
```

Maven Central may answer 429 (Too Many Requests) through the session's proxy; a local init script
`~/.gradle/init.d/central-mirror.gradle` that points `https://repo.maven.apache.org/maven2` repositories (in
`settings.pluginManagement`, `settings.dependencyResolutionManagement` and `allprojects`) at Google's mirror
`https://maven-central.storage-download.googleapis.com/maven2/` avoids it (not part of the repository). Then
`bash scripts/wsl-gradle.sh lintDebug testDebugUnitTest compileDebugAndroidTestKotlin`. `assembleDebug` also needs
`ndk;28.2.13676358`, `cmake;3.22.1` and `bash native/build-ffmpeg.sh`; the emulator suites (step 3) need KVM, which the
container does not have. A signed APK to try on a phone comes from "Run workflow" of `release.yml` with the `version`
input (e.g. `1.3.0-dev1`, see [RELEASE.md](RELEASE.md)).

## 2. Real-protocol tests

```
python3 scripts/fixtures/make_fixture.py         # fixture tree in build/fixture + docs/fork/fixtures/MANIFEST.json (SHA-256)
bash scripts/fixtures/servers.sh up              # Docker: Samba, FTP (2121 normal / 2122 no REST / 2123 truncating / 2124 FTPS), WebDAV, DLNA renderer
bash scripts/wsl-gradle.sh testDebugUnitTest --tests "com.wing.folderplayer.protocol.*" \
     --tests "com.wing.folderplayer.cast.RelayServerTest" $(bash scripts/fixtures/servers.sh props)
bash scripts/fixtures/run-in-network-tests.sh    # DLNA end-to-end inside the Docker network
```

All fixture media are generated by the script (no third-party recordings).

## 3. Android instrumentation (emulators in Docker with KVM)

```
bash scripts/emulator/emu.sh start <avd> <port>          # e.g. API 26 / 33 / 34 / 36 and an API 36 16 KB-page image
bash scripts/emulator/instrument.sh 127.0.0.1:<port> install
bash scripts/emulator/instrument.sh 127.0.0.1:<port> push-fixture
bash scripts/emulator/run-suites.sh 127.0.0.1:<port> [Suite ...]
```

`run-suites.sh` runs every test method in its own process, the permission sequence for `LocalAccessTest`
(grant → revoke images → partial → none → re-grant) and the SAF sequence with a device reboot (`saf-sequence.sh`).
An assumption failure is reported as SKIP and counts as a failure. Run one emulator at a time on machines with limited
memory.

Notes on two test methods: on API 33+ the shell cannot deliver the protected `AUDIO_BECOMING_NOISY` broadcast, so
`PlaybackServiceTest` hands the same intent to the receiver registered by `MusicService` (`MusicService.current`
exists only for that test). AI features are tested against an OpenAI-compatible mock server.

## 4. Native libraries and 16 KB pages

```
bash native/build-ffmpeg.sh             # FFmpeg 7.1.5 from the pinned tarball (sha256 checked)
bash scripts/wsl-gradle.sh assembleDebug
bash scripts/check-16k.sh [apk]         # zipalign -c -P 16 + ELF LOAD alignment for every ABI
```

`check-16k.sh` uses build-tools 35.0.0, the version the release workflow installs (`BUILD_TOOLS`); 34.0.0 has no
`zipalign -P` and the script then fails instead of passing.

The arm64-v8a library was also exercised on an x86_64 emulator through Android's ARM translation
(`adb install --abi arm64-v8a`, then `NativeDecodeTest`).

### 5.28 Faster waveform (1.3.1, 2026-10-23)

a rough trend is enough). Cause: the MediaCodec loop waited up to 10 ms for an input and again for an output buffer on
